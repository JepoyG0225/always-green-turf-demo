1. Signing in & users

The admin lives at www.alwaysgreenturfaz.com/admin (old /dispatch links redirect here). Sign in at /admin/login with your work email and password.

Adding a user

Users are managed in Supabase (the database behind the login), not inside this panel:

  1. Open the Supabase project → Authentication → Users.
  2. Click Add user → Create new user.
  3. Enter their email and a password, and tick Auto Confirm User.
  4. They can now sign in at /admin/login. Any signed-in user has full admin access.

2. Panel layout

The left sidebar is grouped into sections. On mobile the same links appear as tabs across the top. Every list is newest-first, and most rows open a detail popup when clicked.

4. Automations (workflows)

Each automation listens for an event in one system and does something in another. They run automatically — you don't start them by hand.

ArcSite Signed → Jobber NoteAn ArcSite proposal is approved/signedAttaches the signed-proposal PDF as a note on the customer's Jobber quote.

5. Reading execution logs

Two ways to see what an automation did:

  • Per workflow: Workflows → click a workflow → the Executions tab shows that workflow's runs.
  • All at once: the Executions screen lists every run.

Click a run to expand it. Each step shows its input and output, timing, and a status dot:

  • success — the step completed. The run's overall status is success.
  • error — a step failed; the error message is shown and the run status is error.
  • skipped — the run intentionally did nothing (e.g. an ArcSite event that wasn't "approved", or the workflow is paused).
  • dry_run — a test run that read data and reported a plan without writing anything.
Tip: if a step shows error, the message usually says exactly what's wrong (e.g. "No Jobber client found", a QuickBooks auth error, a bad field). That's the first place to look.

6. Pausing a workflow

Open a workflow (Workflows → click it) and use the Published / Unpublished toggle at the top.

  • Published (default) — the workflow runs normally.
  • Unpublished — incoming events are still received but skipped (logged as skipped, nothing is written). Use this to pause an automation without touching the webhook.

7. Updating webhooks

A "webhook" is just a URL that an outside system (GoHighLevel, ArcSite, Jobber) calls when something happens. Each workflow has its own URL. You change where an automation listens by updating the URL in the source system — not inside this panel.

Find a workflow's URL

Open the workflow (Workflows → click it) → the Webhook tab shows the exact POST URL and a Copy button. That's the value to paste into the source system.

GoHighLevel (GHL)

  1. GHL → Automation → Workflows → open the workflow that fires the event (e.g. "Send Appointment").
  2. Open its Webhook / Custom Webhook action.
  3. Set the URL to the workflow's endpoint (from the Webhook tab), method POST, JSON body.
  4. Save/Publish the GHL workflow.

ArcSite

  1. In ArcSite's webhook settings, find the subscription for the event (proposal sent vs proposal approved/signed are separate).
  2. Set its URL to the matching workflow endpoint.
  3. Save. ArcSite usually shows recent delivery attempts — check for a 200 response.

Jobber

Jobber payment events are configured on the Jobber app/webhook side (topic PAYMENT_CREATE → the payment endpoint). This rarely changes.

Important: when you point a source at one of these URLs, turn off the old n8n version of that workflow, or both will run and you'll get duplicates (double invoices, double notes, etc.).

8. Public forms

Two customer/crew-facing forms feed the panel:

  • Warranty claim — /warranty. Submissions appear under Warranty Claims.
  • Job Completed — /job-complete. Give this link to PMs/crews; submissions post to Slack and appear under Job Completions.

9. Troubleshooting

  • Nothing showed up after an event? Open the workflow's Executions tab. No run at all → the source didn't reach us (check the webhook URL/event in that system). A skipped run → a condition wasn't met (e.g. not approved, or the workflow is paused). An error run → read the failing step's message.
  • A workflow is misbehaving — pause it with the Published toggle while you investigate.
  • QuickBooks / Jobber auth errors — the connection may need re-authorizing; contact your admin.
